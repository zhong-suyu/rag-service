# 检索效果评估报告

- 评估集：24 题（正样本 20 / 负样本 4），覆盖选购、维护、故障、使用四类
- 索引：`chroma_db` 中已持久化的真实数据（13 个文档 → 326 chunks，chunk_size=200 / overlap=20）
- 评估口径：top-3 检索，命中 = 返回的 3 个块中至少一块包含该题标准答案里的关键词
- 复现：`.venv\Scripts\python.exe eval\run_eval.py --mode vector|hybrid`

## 两种检索策略对比

| 指标 | 仅向量（vector） | 混合检索（hybrid） | 变化 |
| --- | --- | --- | --- |
| hit@3 命中率 | 75.0% | **95.0%** | +20.0pp |
| MRR | 0.667 | **0.892** | +0.225 |
| 来源命中率 | 90.0% | **100.0%** | +10.0pp |
| 平均检索耗时 | 263 ms | 342 ms | +79 ms |
| P95 检索耗时 | 584 ms | 870 ms | +286 ms |

> hybrid 的平均耗时里包含了进程内第一次检索时构建 BM25 索引的开销（326 条切片的 jieba 分词），
> 索引构建完成后单题检索稳定在 150–200ms，与纯向量基本持平。

## 为什么混合检索能提升

纯向量检索在语义相近的表述上更强，但对**参数类问题**不敏感：

- 「地毯场景需要多大吸力？」→ 语义上和「吸力参数」很近，但答案块里写的是 `地毯场景需≥4000Pa`，
  这个数字在向量空间里没有区分度，top-3 常常召不回正确的块
- 反过来 BM25 靠词面命中，`4000Pa / 2.5L / 3米` 这类数字+单位能精确抓住
- 两路各取 10 条候选，用 RRF（`score = Σ 1/(60+rank)`）融合，取前 3

纯向量 miss 的 5 题（q02 4000Pa、q05 2.5L、q16 3米、q19 单独开启拖地、q20 先扫后拖）
在 hybrid 下只剩 q05 仍漏召，其余全部召回。

## 剩余的漏召（q05）

「集尘袋容量建议多大才能减少更换频率？」答案块确实存在
（`8. 集尘功能：…集尘袋容量≥2.5L可减少更换频率…`），BM25 也把它排在第 1，
但纯向量一路没召回它，RRF 融合后掉到第 4 位。

这是 RRF 的典型取舍：**只在一路排第 1、另一路完全没出现**的块，会输给「两路都排中游」的块。
下一步可以做的优化（本次未实现）：给单路 top-1 加保底名额，或改成归一化分数加权融合。

## 负样本（库里没有答案）

| 问题 | top1 距离 |
| --- | --- |
| 这款扫地机器人的售价是多少？ | 0.529 |
| 扫地机器人可以帮忙洗衣服吗？ | 0.625 |
| 机器人能自动爬楼梯上楼吗？ | 0.694 |
| 扫地机器人可以给手机充电吗？ | 0.603 |

结论：**只靠距离阈值做拒答并不可靠**。正样本里命中题的 top1 距离最高到 0.879，
比部分负样本还大，说明在这份垂直领域语料上，绝对距离分不清「相关」和「不相关」。
所以本次没有用距离阈值做拒答，而是靠提示词约束（资料里没有就明确说明「参考资料中未提及」）
+ 出处标注，让人能自己判断答案是否可信。
