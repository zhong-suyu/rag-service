# 检索效果评估报告

- 评估集：**80 题**（正样本 68 / 负样本 12），覆盖选购、维护、故障、使用、技术五类
- 索引：`chroma_db` 中已持久化的真实数据（13 个文档 → 326 chunks，chunk_size=200 / overlap=20）
- 评估口径：top-3 检索，命中 = 返回的 3 个块中至少一块包含该题标准答案里的关键词
- 题库自检：`eval/check_questions.py`（关键词必须存在于库中，且命中块数 ≤ 8，避免用泛词凑分）
- 复现：`.venv\Scripts\python.exe eval\run_eval.py --mode vector|hybrid`

## 样本量与统计约束

68 道正样本下，95% 置信区间约 ±8pp（`1.96*sqrt(p*(1-p)/n)`），所以对外应说"约 87%"，而不是精确的 86.8%。
两个模式之间的 19pp 差距（67.6% → 86.8%）明显大于单侧误差，结论可信。

## 两种检索策略对比

| 指标 | 仅向量（vector） | 混合检索（hybrid） | 变化 |
| --- | --- | --- | --- |
| hit@3 命中率 | 67.6%（46/68） | **86.8%（59/68）** | **+19.2pp** |
| MRR | 0.549 | **0.725** | +0.176 |
| 来源命中率 | 89.7% | **95.6%** | +5.9pp |
| 平均检索耗时 | 235 ms | 218 ms（索引热身后） | ≈ 持平 |
| P95 检索耗时 | 456 ms | 370 ms | — |

> hybrid 的平均耗时反而略低，因为纯向量是逐题走 embedding API（有网络抖动），
> BM25 是本地计算；hybrid 的冷启动（首次建 BM25 索引约 1 秒）不计入单题均值。

## 为什么混合检索能提升

纯向量检索擅长"语义相近"，但对**参数类问题**不敏感。答案块里写的是 `地毯场景需≥4000Pa`，
这个数字只占 200 字里的几个字符，对 1024 维向量方向的影响几乎可以忽略，
所以"地毯需要多大吸力"和"地毯清洁效果如何提升"在向量空间里几乎一样近。

BM25 靠词面命中：`4000Pa / 2.5L / 3米 / 300W` 这类数字+单位在库里只出现 1~2 次，
IDF 权重极高，一票就能命中。两路各取 10 条候选，用 RRF（`Σ 1/(60+rank)`）融合取前 3。

## 纯向量漏召的 22 题，混合检索救回 13 题

纯向量未命中的 22 题中，hybrid 修好了 13 题：q02/q16/q19/q20/q22/q23/q27/q40/q42/q44/q47/q53/q60。

仍然漏召的 9 题：

| 编号 | 问题 | 关键词 | 漏召原因分析 |
| --- | --- | --- | --- |
| q05 | 集尘袋容量建议多大 | `2.5L` | BM25 排第 1，但向量一路没召回，RRF 融合后掉到第 4（单路第一 < 两路中游） |
| q09 | 充电触点怎么清洁 | `金属触点` | 关键词只在 1 块中，且该块同时含 5~6 条维护规则，向量方向被平均稀释 |
| q12 | 电池鼓包怎么处理 | `鼓包则立即更换` | 答案被 200 字切分横跨两块，问题块召回、答案块未召回 |
| q14 | 主刷不旋转原因 | `主刷电机` | 与 q12 同因：条目跨块，前块只有现象没有原因 |
| q24 | 吸尘电机功率 | `300W` | 答案块语义与"电机功率"相近的块过多，两路排名都在 4~6 |
| q41 | 主刷咔咔异响 | `轴承` | 关键词在同块中靠后位置，块前半段是别的故障，语义不占优 |
| q51 | 床底沙发底怎么扫 | `深度清扫` | 与"能否清理床底"块高度相似，正确块被同义块挤掉 |
| q54 | 水箱密封圈老化 | `密封圈属于易损件` | 密封圈相关块跨"维护/扫拖/选购"三个文件，同义竞争激烈 |
| q66 | 防跌落要清洁哪个传感器 | `悬崖传感器` | PDF 块与 txt 块都讲防跌落，正确答案块排名 4 |

共性结论：**剩下的漏召大多不是"检索方式不够"，而是 chunk_size=200 把一条完整规则切成了两块**
（q12/q14 最典型）。这为下一步优化指了明确方向：对"现象+检测+修复"这类长句条目，按条目边界切而不是按字符数切。

## 负样本（库里没有答案，12 题）

| 问题 | top1 距离 |
| --- | --- |
| 扫地机器人的售价是多少？ | 0.529 |
| 电池是什么品牌的？ | 0.659 |
| 能帮忙洗衣服吗？ | 0.625 |
| 能自动爬楼梯吗？ | 0.694 |
| 能给手机充电吗？ | 0.603 |
| 能给孩子讲睡前故事吗？ | 0.746 |
| 能帮忙遛狗吗？ | 0.773 |
| 能用来擦窗户吗？ | 0.694 |
| 支持人脸识别解锁吗？ | 0.610 |
| 在哪个工厂生产？ | 0.861 |
| 能烘焙蛋糕吗？ | 0.729 |
| 有几档氛围灯颜色？ | 0.848 |

正样本 top1 距离范围：**0.237 ~ 0.963**。与负样本的 0.529~0.861 **完全重叠**。

结论：**绝对距离阈值无法用于拒答**。任何阈值都会同时误杀命中题、放过负样本。
根本原因是 Chroma 默认 L2 距离、且语料单一领域（全部在聊扫地机器人），
"不相关"的块离查询也不远。改由提示词约束（资料里没有就说明"未提及"）+ 出处标注处理。

若将来要做拒答，正确方向是：rerank 后的相关性分数、或 `top1-top2` 相对差距，而不是原始 L2 距离。

## 尝试过但未采用的方案

**单路 top-1 保底融合**（先占两路第 1 名，再按 RRF 填空位）。

在旧的 20 题小样本上实测过：

| 融合方式 | hit@3 | MRR |
| --- | --- | --- |
| 纯 RRF（现方案） | 95.0% | 0.892 |
| 只保 BM25 top1 | 100.0% | 0.842 |
| 两路 top1 保底 | 100.0% | 0.792 |

**命中是拿排序换来的**：保底把原本靠 RRF 排第 1 的正确答案挤到第 2/3 位。
top-3 全部进 prompt 且排名越靠前权重越大，所以未采用。
后续可在 80 题集上重测，但当前判断是"不值得为个别漏召改全局排序策略"。
